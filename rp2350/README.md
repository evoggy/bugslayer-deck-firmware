# RP2350B firmware — sniffing, control plane, FX2 boot

The instrument. Everything the deck actually does lives here.

## Responsibilities

1. **Capture** — PIO sniffs the 16 CF expansion signals; DMA rings into RAM; blocks framed
   per [../docs/protocol.md](../docs/protocol.md).
2. **Control plane** — USB CDC (v0) command loop. Owns arming, session IDs, status.
3. **FX2 ownership** — holds `FX_RESET#`, serves the boot image as an emulated I²C EEPROM at
   0xA2 on GP6/GP7, and generates IFCLK.
4. **Egress** — PIO write engine into the FX2 slave FIFO, or the same blocks over its own USB.
5. **Board housekeeping** — VCC/VCOM switches, I²C pull-ups, the USB/UART mux, ADC telemetry.

## Toolchain

Pico SDK + CMake + `arm-none-eabi-gcc`, `PICO_BOARD` set for RP2350B (`rp2350` / a custom
board header — 48 GPIOs, not the Pico 2's 30).

```
mkdir build && cd build
cmake -DPICO_SDK_PATH=... -DPICO_PLATFORM=rp2350 ..
make
```

## Two things to get right early

**PIO base 16.** Put the capture SM and the FX2 write SM on the *same* PIO block with
`pio_set_gpio_base(pio, 16)`. You still pass **real GP numbers** to every `sm_config_set_*_pins()`
call — on RP2350B the SDK translates for the base — but a configuration that cannot fit one
32-pin window makes `pio_sm_init()` return `PICO_ERROR_BAD_ALIGNMENT`.

**IFCLK before reset release.** The FX2's boot firmware writes `IFCONFIG` and the FIFO
registers, and with `IFCLKSRC=0` that block is clocked from GP40 — a dead clock hangs the 8051.
`fx2_write.pio`'s `clk_only` entry point exists for exactly this. Afterwards the FX2 does no
register writes, so a stalled write engine freezing the clock is harmless.

## Layout

```
src/      application, control plane, USB
pio/      .pio programs (capture, FX2 write)
```

The FX2 C2 boot image is generated by `../fx2/` and committed as a C array, so this firmware
builds without SDCC installed.

## Build

```
cmake -B build -DPICO_SDK_PATH=/path/to/pico-sdk
cmake --build build -j
```

Produces `build/bugslayer_deck.uf2`. Verified against pico-sdk 2.2.0 and
arm-none-eabi-gcc 13.2.

## Status

Stages 0 and 1 implemented and building; nothing has run on hardware. Connect over the CDC
port and type `help`. Typical stage 1 session:

```
fx2 up            # IFCLK starts, then FX_RESET# releases
                  # (host: fx2tool load bugslayer-fx2.ihex)
clk 6000000       # walk the ladder from the slow end
arm
                  # (host: python3 host/fx2_counter_test.py --duration 60)
disarm
```

Not yet: capture, the block framing from ../docs/protocol.md, EEPROM emulation, PKTEND on
disarm. See [../docs/bringup-plan.md](../docs/bringup-plan.md) stages 2–5.
